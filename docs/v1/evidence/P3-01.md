## Proved

- `ctc contract build` combines an inspected app model, captured design spec, explicit correspondence manifest, explicit behavior manifest, and any exact-scope owner approvals into a schema-valid, hash-pinned `RetrofitContract`.
- Design identities, existing UI symbols, existing actions, acceptance contexts, evidence, approvals, source files, and allowed paths are semantically cross-checked rather than accepted on schema shape alone.
- Mappings, capabilities, behavior obligations, golden policy, budgets, commands, and edit permissions are authored inputs; the builder does not infer them from names, strings, or heuristic build clues.
- Requirements are deterministically normalized and hashed, and the same inputs plus `--created-at` produce byte-identical contract and packet artifacts.
- `ctc agent packet` revalidates every hash-pinned input and rebuilds the contract before rendering constrained JSON and Markdown from one canonical packet model.
- Packet output includes source paths and hashes, exact mappings, behavior obligations, path boundaries, verification commands, contexts, and numeric budgets without claiming those commands ran.
- Source-evidence bytes are rehashed, including Git-ignored files, and exact source locations must resolve to their evidence. Stale sources invalidate both contract construction and packet reconstruction.
- Contract and packet outputs cannot overwrite their own inputs, approvals, source contract, or workspace marker; final symlinks and workspace escapes remain rejected.
- Authored blocking capability or uncertainty emits a reviewable artifact with exit `2`, never a verification `PASS`.
